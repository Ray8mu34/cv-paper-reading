# 四种交付模式与原文顺序

`analysis.json` 是共享科学状态。`report.md/report.html` 面向读者，`analysis-notes.md/validation/` 保存原文结构规划、覆盖、科学记录与真实审读轨迹。构建器不能自动阅读论文或判断文字质量。

|模式|读者要做什么|默认组织方式|
|---|---|---|
|quick|判断是否值得深入读|按现有摘要/部分材料报告研究问题、贡献、结果和获取范围；不假装遍历未读章节|
|deep-md|理解论文整体论证与关键数学|简要概览 → 前置原文论证路线 → **按原文主要章节顺序**逐节讲解和精讲 → 独立评价 → 进一步阅读/后置详细原文地图|
|interactive-html|深读且通过有益可操作的反事实补充理解|保持 deep 的原文顺序与深度；原图在方法/实验相应位置，交互只在真正改善理解时启用|
|critical-review|准确理解并审查论文结论|先按原文完整重建研究动机、方法和实验证据，再单设集中独立评价；直接影响当前实验解释的条件仍可就地说明|

新任务使用 schema 1.3：`reader.organization="paper-order"`，`argument_route` 为前置简短论证路线，`roadmap` 为后置精确 §/页码表，`sections[].source_sections` 映射原文章节，`throughline/connections` 仅在论证关系复杂时作可选内部笔记。只有明确的重组需求才选 `restructured` 并记录具体理由，保持目录覆盖。旧 schema 1.0–1.2 仍可构建，但不自动补齐映射或变更历史布局。

原文每个主要章节都应有具体阐释，尤其不能把先行研究比较、关键挑战、方案选择理由压成一行。重要数学可以展开；篇幅由推导和实验解读的难度决定。批评和技术核查不能抢在作者论证之前主导阅读。科学条件在真正影响结论的地方出现一次，执行与复现状态只保留内部，避免长段防御性措辞。

交付前按 [轻量质量检查](quality-gates.md) 一次性核对原文章序、关键事实与产物即可；`reader-review.json` 及完整读者复述只在明确要求教学效果测试时使用。quick 只声明实际阅读范围，深读保持科学深度而不增加额外验收轮次。
