# 轻量质量检查：原文忠实、解释清楚、产物可用

**普通精读仅做一次合并式检查**，不另起读者测试或生成第二篇审查报告。大部分科学核查应在阅读原文、解释对应方法和实验时完成；交付前只复核影响结果的重点。

1. **原文结构**：`reader.roadmap` 对照已取得论文的真实主要章节，正文 `source_sections` 是否覆盖并保持正确次序；作者的动机、关键方法选择、主要实验及结论是否被不合理省略。程序仅能检查已记录地图，不能识别地图本身遗漏的 PDF 章节。
2. **技术与证据**：关键公式和变量是否准确、主要原图与图注是否被正确理解、重要数字及比较条件是否对得上原文。科学上会改变结论的限制就地写一次，不做所有可能反例的枚举；独立评价集中在论文论证之后。
3. **表达与交付**：方法出现前是否讲明它解决什么问题；章节之间是否自然过渡；技术分析是否帮助解释而非抢走主线；删除重复的防御性限制和无关执行日志。运行一次报告构建与产物一致性校验，报告成功生成即可交付。

发现具体不一致就改对应位置，必要时只重查受影响内容。**不强制**四分之一处暂停测试、逐章无提示复述、人工复述登记、独立读者评分、多轮评审、`reader-review.json`、训练复现和 UI 回归。这些只有在用户明确要求专项评估、或相应代码发生变更时才执行。不得把“测试全部通过”当作论文解释自然可信的证据。

```sh
python scripts/validate_skill.py --analysis WORK/analysis.json --require-artifacts
```

Markdown-only 使用 `--md-only`。需要单独的读者研究时，`prepare_reader_review.py` 与 `--require-reader-review` 可选使用，但不是正常报告生产链的一部分。
