# 原文优先、按需深入的轻量工作流

**目标**：让具有 CV/ML 基础但初读论文的研究生沿作者原有论证理解论文，必要时补充技术深度。研究质量取决于解释是否扎实，不以内部日志数量、反复自测或测试轮数衡量。

## 1. 阅读原文，顺手建立一份章节地图

固定论文版本，阅读实际取得的正文、关键图表和图注，以及影响核心结论的附录。依**真实原文章序**填写 `reader.roadmap`：主要章号、标题、该章在整个论证中回答什么、相关重要图/式及页码。图表和方法动机在阅读时一起记录即可，不额外进行第二轮“制作讲解路线”的阅读。

检查关键因果链：作者为何研究这个问题、现有做法有哪些实际限制、为什么采用这种技术选择、实验检验哪些主张。常规背景文献清单、重复参数和无关附录可概括；有决定性方法选择依据的段落不可省略。论文没有写的作者尝试和心理过程不可编造。

从这份地图直接生成开篇 `reader.argument_route`（一段简短的原文章节论证路线），`reader.overview` 则交代问题、核心方案和重要结果。仅在论文多线并行或理解依赖确实复杂时，才补充可选的内部 `reader.throughline`；这不是第二份强制笔记。

## 2. 保留论证顺序，在原文章节内讲深

默认为 `reader.organization="paper-order"`。每个主要正文 `sections[]` 填真实 `source_sections`，按 `reader.roadmap` 顺序排列。相邻短章可合写，一个方法章可拆为连续几节；正常不要求原文每段都有对应段落。每节正文直接回答“为什么需要这一步—作者做了什么—怎样承接下一步”，而不用另填逐章 `needs/adds` 表。`reader.connections` **可选**，只有复杂前提依赖、读者容易失去上下文时才使用。

技术细节要深，但安排在其被需要的位置：先讲研究困难与方法选择，再解释机制、变量、公式推导、训练与推断。首次出现的术语可以用一小段先修桥梁；无需为教学例子调整整篇章节顺序。原论文关键整体框架图放在方法处，决定性实验图放在原本回答的问题旁，并解释图像、坐标、比较对象和结果意义。

在各原文实验章节解释“问题—主要设置与对照—实际观察—支持的主张”。区分作者证据、独立推导、教学示例与解释者判断。真正改变某项结果含义的科学条件就在该处说明一次；延伸的独立评价放在作者主要论证之后，避免段段免责声明。附录和内部联系资料只用于值得深入的细节，不代替正文核心论证。

程序能检查**已登记 roadmap** 的章节覆盖和正文相对顺序，但无法知道 Agent 是否遗漏 PDF 中真实存在的章节，因此阅读时需对照一次实际目录。只有用户明确要求或原章序确有不能通过局部解释解决的先修障碍，才设置 `restructured` 并填写具体 `departure_reason`，仍须覆盖主要原文章节。

## 3. 一次合并式交付检查，不做重复读者测试

生成实际报告后，一次性完成以下核对即可：正文是否覆盖主要原文章节且顺序正确；动机和方法选择是否已经讲清；最关键的公式、图表、数值和结论是否与原文相符；文件能否成功生成和打开。只对发现的真实错误做局部修正，改动后验证受影响的部分。检查的目标是避免明显错误和断裂，不是在已经写好的报告之外再写一份复述。

**默认不做**四分之一阅读暂停、逐章无提示复述、模拟独立读者、多轮作者自我评分、强制 `validation/reader-review.json`、训练/复现实验或 UI 全量回归。不要为了“检验理解”另开模型调用，也不要将内部审查过程写进正文。独立读者评测或严格教学效果评估只在用户明确提出时启用保留的 `scripts/prepare_reader_review.py` 和 `--require-reader-review`，不能把作者自查冒充独立验证。

常规构建与验证：

```sh
python scripts/build_report.py --analysis WORK/analysis.json
python scripts/validate_skill.py --analysis WORK/analysis.json --require-artifacts
```

只生成 Markdown 时，两条命令加 `--md-only`。`pytest`、打包、发布哈希/浏览器检查只在开发修改 Skill 时使用，**不是每篇论文的步骤**。
